**2026-08-13 · Structural investment is harness-owned at four points; judgment fills them — the anti-spaghetti design.** The owner's concern, and it's the classic agile failure: small loops that are each proven good can still stack jank, because stateless agent sessions don't accumulate the pain that triggers human refactoring, and nothing in a greedy loop rewards stopping. Concretely: (1) a strain ledger in `state.md` — working around instead of through anything writes a line, so pain survives between sessions; (2) shaping starts by reading it — twice-recorded strain becomes the next piece or is deferred visibly; (3) the structure verdict belongs to the independent reviewer (sound / straining / fighting), because the builder always has momentum and the party that wants to keep building never decides whether building pauses — two straining in a row, or one fighting, forces structural work; (4) predictable foundations are named at shaping time with the trigger that makes each due, and fire as ordinary pieces. Structural work is first-class: shaped and proven like a feature, proof = behavior unchanged and the strain gone. Considered instead: leaving it entirely to model/user judgment (rejected — the momentum conflict-of-interest is structural, same shape as self-review); mandatory periodic architecture reviews (rejected — cadence-based ceremony is how old Speck grew 183 findings with zero real defects); upfront foundation phases (rejected — old Speck's foundations were mostly documents about foundations; Pilot had an architecture.md and no walking skeleton). Reopens if a real product accumulates spaghetti anyway — measured by refactor pieces repeatedly discovering strain no one recorded.

**2026-08-13 · v1 is accepted on confidence, not on a contest — owner decision.** The head-to-head benchmark against Speck v11 is descoped. v1 is good when the owner's agent is confident that: all valuable, non-obvious old-Speck learnings are adopted; the methodology demonstrably works (dev suite green, real exercises built with it end to end); and it's a true value-add over a no-harness agent — judged on the field record and how frontier models actually work. v1's target use: rebooting the Pilot project greenfield (new repo, product brief engineered from the current project). Consequences: the fixtures file becomes a designed-but-shelved contest (kept — its planted-bug classes still seed the dev suite); the upgrader drops off the v1 critical path (greenfield reboot needs a fresh-start path, not conversion — promise 5 stays for a later version); v1's proof burden shifts to the dev suite plus real product exercises plus a decorrelated confidence audit against the owner's goal text. What must newly exist for v1: product-shaping guidance (jobs-to-be-done, first principles, AI-first "year 2126" bar, magic moments) and UI/experience judgment — the parts of old Speck that made products stand out, not just correct.

**2026-08-13 · Kernel development runs as an evolution loop with a train/test split.** The frozen contest stays the held-out exam — never iterated against, plantings secret. What was missing is the *search side*: a cheap development suite (tiny scored tasks on toy repos, plantings visible, runnable in minutes) that kernel changes are measured on between contests. Method changes follow candidate discipline: one mechanism per change, a falsifiable hypothesis with a predicted effect written in the work file, the measured result written back — which is also how promise 8's "predicted benefit, measured or retired" actually gets operationalized. Analysis reads real session transcripts and run logs, not summaries; and a change prompted by a dev-suite failure must pass the generality test — would it help across many unfamiliar tasks, or just this one? Pattern adapted from Stanford's Meta-Harness (github.com/stanford-iris-lab/meta-harness, arXiv:2603.28052), whose reference loop burns ~$500 per iteration — ours must cost pennies, so dev tasks stay pulse-sized. Considered instead: iterating directly against the contest (rejected — overfits the exam and breaks its integrity rules) and no quantitative loop at all, self-hosting friction only (rejected — friction finds usability problems but can't measure detection or cost regressions). Reopens if the dev suite and contest results ever diverge badly — that means the dev suite drifted from what matters.

**2026-08-13 · One method, many subjects.** The method surface (`AGENTS.md`, the skills, later the upgrader) is byte-identical in every repository it governs; only the four product files differ. This repository is not special — it's an ordinary Speck Next repo whose product happens to be the kernel, which is what makes self-hosting and installability the same thing rather than a conflict. Installing into a product repo means placing the method surface and creating (or converting) that product's four files; the kernel repo's own product files never ship anywhere. Product-specific standing guidance (stack, commands, conventions) belongs in the product's own files, which agents always read anyway — the method page stays identical everywhere; the exact seam gets settled when the upgrader is built. Considered instead: a special dev-mode method page for this repo (rejected — then we'd never be testing the real thing), and per-repo customized method pages (rejected — 5 diverging pages is the old upgrade treadmill reborn). Reopens if a product genuinely needs standing agent instructions that fit none of its four files. Editing `AGENTS.md` in this repo is always substantial work — it changes the governor — so it takes the full loop and independent review.

**2026-08-13 · Old Speck's lessons live in four homes, and thinness is only honest with all four.** The kernel page carries only what every piece of work needs. The rest of the validated knowledge lands where it's actually used: dense on-demand references inside skills and extra-care packs (first harvest: the attack playbook in `independent-review`, distilled from old Speck's audit doctrine and the field defects); all era knowledge in the upgrader; and the sharpest form — the lessons as *tests*: the contest's planted-bug classes are the old scars operationalized, and the kernel must match full-strength v11 per class or lose. Old Speck's repo stays intact as the quarry, and any mechanism can re-enter through the six questions with evidence. What we refuse: bulk-importing 93k lines of enforcement plumbing and calling it respect — most of that mass was machinery about machinery, and the knowledge inside it was always small. Reopens per class: any planted-bug class the kernel misses that v11 catches pulls the relevant old mechanism back through the six questions.

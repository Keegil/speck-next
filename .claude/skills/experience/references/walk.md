# Walk the affected user job

Use the real product as the person affected by this change. Select the checks that could change your conclusion; this is a menu, not a required tour of every screen.

- Read the user's intent and any relevant promise or declared feel. Name the build or commit you use.
- Start where this person would start. Use fresh storage or a second account when onboarding, privacy, or account changes make that important.
- Complete the affected job, including the meaningful states this change touches. If a concrete failure affects a longer sequence, run that complete sequence again after the repair.
- Where features interact, try a fresh combination derived from the promised job, including relevant failure behavior. Passing isolated examples does not establish that the combination works.
- When the product claims to save, send, or generate something, verify the resulting state. Use a safe stand-in for an irreversible action and name what it cannot prove.
- Choose likely recovery problems: interruption, missing data, rejected input, or network failure. Add weak permissions and cross-account checks when the affected behavior needs them.
- For a visual change, inspect the rendered result. Save and open screenshots when they help identify the defect or support the conclusion. Check readability, containment, hierarchy, and the intended feel.
- Use keyboard, accessibility, mobile, or text-scaling checks when the changed interaction could affect them. Preserve useful output rather than collecting reports by default.

Judge taste against the product's declared feel. A broken stated rule is a concrete finding; a preference is your response, not an objective defect. Surface an owner choice only when it changes the result and cannot be settled from the brief.

Return the result, the actions you actually ran, concrete findings, and any material limits. Explain whether the affected job works and feels appropriate, with evidence for those claims. An independent reviewer can use this record and decide acceptance in the same context.

Target: CONTRACT.md v0 + docs/benchmark/fixtures.md v0 + deletion-manifest v0 + README v0. Reviewer instruction: fresh context, refute.

---

The draft does not survive as written. The product thesis is credible; the contract and benchmark currently are not.

1. **P0 — "Frozen before design" is contradicted by the fixture itself.** "Before any successor design existed" — yet the document names and the speck-next adoption behavior referenced in the fixtures are successor design choices, not raw evidence. Fix: separate an immutable pre-design evidence pack from the derived benchmark protocol; publish hashes and timestamps; if no artifact predates the design, retract the claim and treat this as a retrospective corpus requiring an independently held validation set.
2. **P0 — The successor author can write the rubric that declares the successor successful.** A weighted score can let cheapness compensate for missed security defects or failed adoption. Fix: make contract promises non-compensatory gates now (adoption fidelity, no overclaim, truth-detection non-regression, product-quality floor, hard budgets — each must pass); a decorrelated reviewer locks and hashes the rubric before implementation; no changes after any successor run.
3. **P0 — The public defect corpus measures memorization, not truth-detection.** The successor author knows every class and can encode an eleven-item inspection checklist. Fix: pre-register mutation families; an independent custodian creates withheld variants and clean twins; the implementation author and task agent must not see defect locations or class labels before execution.
4. **P0 — Promise 3's denominator is not covered by T05–T10.** `banned-language`, `phantom-promise`, `unreachable-excuse` have no task. Fix: publish a class-by-task coverage matrix covering every frozen class with defective and clean cases; freeze the actual v11.2.0 baseline results; require non-regression per critical class, not on an aggregate.
5. **P0 — A system that refuses everything can win truth-detection.** Every truth task contains a defect; no false-positive or successful-delivery constraint exists. Fix: matched clean tasks, a false-positive ceiling, and a delivered-change requirement; blanket refusal must fail.
6. **P1 — The "frozen prompts" are placeholders, not executable fixtures.** Fix: freeze exact prompts, planted patches, owner steer scripts, repository setup, model snapshot, permissions, time limits, token accounting, repetition count, and blind-judge protocol in executable manifests.
7. **P0 — The iterative acceptance criterion is trivially gameable.** One enormous first plan, or a big-bang implementation followed by something labeled "demo", passes. Fix: bound the first slice by elapsed time and product scope; require evidence the owner operated the real surface; freeze a steer that materially changes increment two; cap work completed before the steer; add a new-dependency task requiring an actual round-trip before design locks.
8. **P0 — Universal seamless adoption contradicts the refusal escape hatch.** A report explaining that adoption failed is safe behavior, but not seamless adoption. Fix: make migration total for the promised input domain — preserving uncertainty as explicit unresolved state without repair — or narrow the promise with explicit owner approval (it is a verbatim owner constraint).
9. **P0 — T11–T13 cannot prove "any version, any project".** "speilet or flyt" lets the author select the easier repository; idealized synthetic fixtures do not represent partially upgraded or schema-less repositories. Fix: run both repositories per era; add adversarial mutations (partial migrations, renamed artifacts, custom files, schema-less prose, large evidence trees, conflicting state).
10. **P0 — Adoption fidelity has no independent oracle.** The migration author can archive everything, write a vague summary, and declare the mapping conservative. Fix: an independently authored source ledger per fixture (every live promise, decision, defect, uncertainty, evidence link, in-flight item); stable lineage into the destination; zero unexplained orphans; blind semantic review; archived bytes do not count as mapped truth.
11. **P0 — The transactional promise ignores ordinary dirty-repository states.** Fix: define and test preflight, isolation, collision handling, interruption recovery, idempotent retry, preservation of staged/unstaged changes, and successful revert; the adopter must never absorb unrelated user work into its commit.
12. **P1 — Preserved legacy history conflicts with footprint and zero-legacy operation.** Old AGENTS.md, adapters, hooks may remain discoverable or executable. Fix: define active vs archive footprint; quarantine legacy instructions outside agent discovery paths; record archive hashes; make a fresh-agent loader trace part of adoption acceptance; T14 should resume migrated in-flight work, not merely fix a typo.
13. **P1 — README postpones the exact adoption case the contract claims to support.** "Stable work boundaries" conflicts with T13's mid-epic adoption. Fix: remove the phrase; "one-way" means direction, not irreversibility; require mid-flight adoption before claiming seamlessness.
14. **P1 — `state.md` has no defined source of truth.** Fix: canonical inputs, schema, deterministic generation, freshness rules, evidence lineage, and a version-by-version readiness crosswalk with frozen examples of every partial mapping.
15. **P0 — The deletion manifest drops the two protections the failure record says actually worked.** Doctrine and state are not structural mechanisms. Fix: a minimal kernel mechanism — every objectively substantive change automatically invokes a fresh-context evaluator that exercises the real path, uses the relevant least-privileged principal, demonstrates a positive/fault control, and records provenance in generated state; the author cannot waive or certify that gate.
16. **P1 — The author still decides when rigor applies.** Fix: enumerable risk triggers; the author may elevate rigor but not downgrade it; an independent evaluator owns uncertain classification; benchmark the boundary cases.
17. **P1 — The zero-jargon test can be passed by disguising jargon as ordinary words.** Fix: test owner comprehension and task completion without a glossary, not token choice.
18. **P1 — The size budgets leave accounting loopholes.** Hidden or fetched capabilities uncapped; "installed footprint", "always-on doctrine", "unit of work" undefined; the generated index may become an uncounted artifact. Fix: a normative counter covering all entry points, packs, adapters, fetched content, symlinks, indexes, and bytes/tokens actually loaded per run; positive controls proving CI fails when each budget is exceeded.
19. **P1 — The anti-accretion mechanism is already becoming a compliance system.** Five metadata fields per mechanism, five-property matrices per decision, a release ritual — the same locally-reasonable ever-growing self-description pattern that produced v11. Fix: one bounded kernel registry, one row per capability, framework repo only, populated from benchmark evidence; no per-consumer metadata; no enforcement layer for the registry.
20. **P1 — Falsification is discretionary.** Slices, retries, aggregation, and decision authority unspecified; budget rises can retroactively rescue the thesis. Fix: predeclare the two slices, task set, attempt count, immutable results, and decision rule; any P0 gate failure falsifies the slice; budget increases require a new owner-approved contract version.
21. **P2 — The frozen field snapshots are not portable evidence.** A SHA is unusable without an accessible object database. Fix: content-addressed git bundles or sanitized fixture snapshots with checksums.

**Verdict: No.** The underlying clean-sheet thesis remains worth testing, but this contract does not survive yet. Its core adoption promise is internally contradictory, and its benchmark can be authored, weighted, overfit, and judged by the same side it is meant to falsify. Fixing that requires a new independently locked evidence-and-rubric layer and either a genuinely total adopter or an explicit owner-approved narrowing of "100% seamless"; those are contract changes, not implementation details.

# What the second campaign taught the kernel

**The campaign:** the first product piece to run the v5 hearing in anger, on a real product with real accounts, private data, and a deployed production surface. It landed after four route-backs in one judgment line. The campaign's primary record lives with the product's own repo; this file carries only what generalizes, and the adopting session's census pass runs against that record where it lives.

**Outcome sought:** the four disciplines the campaign had to invent land in the kernel in their smallest form, and one existing law gets one sentence sharper — so the next campaign's first hearing gets them for free. Nothing lands on this file's say-so: adoption is a kernel piece, census-first, through this repo's own loop.

**How I'll know it works:** at the next campaign's first hearing, the experiencer's record opens with a subject-identity proof without anyone inventing it; no two runs share an instrument; an owner-iteration stretch batches into a hearing whose receipt enumerates its deltas mechanically; and a judge holding an owner-call finding files it instead of routing on it.

---

## What the hearing proved first

The v5 design held under real fire. Four rounds of route-back → fix → re-experience → re-judge converged instead of looping: judges verified routed findings in source rather than on testimony, ordered runs where evidence was thin instead of ruling on gaps, and ruled land plainly when the piece had earned it. Judge continuity worked as law — each round's judges treated the prior rulings as binding, and one defect class was recognized across three different surfaces *because* the line remembered itself. The second-judge rule produced independent convergence every round. The literal-Built gate and receipt-at-dispatch held throughout (one late receipt, caught by a judge's own housekeeping order). And the owner's felt gate composed with the agent gates instead of substituting for them — he graded what only he can feel while the judges kept routing on truth breaks he had not seen.

## Gap 1 — the experiencer's subject identity must be proven, not assumed

Three rounds of records were void because the stand-in session the runs believed they were walking had silently failed to plant — the mechanism used could not actually set a session on the deployed surface, and it failed without any error. Each run then walked whatever session the shared browser environment already held, and returned a confident, detailed, wrong record. The failure was invisible precisely because a run on the wrong subject still renders screens and still reads as evidence.

The kernel's form, one law in the `experience` skill: **on any product with sessions or accounts, the record opens with a subject-identity proof, or it is void.** Clear all state → read the product's own who-am-I surface and quote it (it must show *nobody*) → establish the stand-in through a mechanism that can actually do so → read who-am-I again and quote it (it must match the run's brief exactly) → only then walk. Both reads verbatim in the record; either wrong ⇒ the run stops and says so rather than dressing up what it could not reach.

## Gap 2 — a shared instrument gets one driver

Two further rounds were destroyed by concurrency on one shared instrument: once by the conductor driving it in the middle of a live run to take its own measurement, once by two runs dispatched in parallel into the same environment, which walked each other's subjects. The kernel's form, one sentence in the `experience` skill's dispatch law: **hearing runs that touch a shared instrument run sequentially, each on its own subject, and the conductor does not touch the instrument while a run is live.**

## Gap 3 — the hearing summons under owner iteration, with mechanical delta enumeration

A multi-day stretch of owner-directed iteration shipped substantial changes — including protected-code surfaces — with zero hearings, and it was the owner who caught it, not any gate. The rule the campaign then ran, which held to the end: **the owner being in the room never switches the hearing off; deltas may batch into one hearing, but a delta touching protected code hears before it ships, and "the owner approved the feel" is never the judge's ruling.** The companion matters as much: a batched receipt written from memory omitted a delta, so the campaign made enumeration mechanical — the receipt's delta list derives from the commit range, with the historical omission kept as the positive control. The kernel's form: the batching rule lands in the build loop beside the existing owner-in-the-room sentence (which today governs only the state rewrite), plus one line that a batched hearing's receipt enumerates its deltas from the commit range, never from recollection.

## Gap 4 — the judge's third lane: the owner's questions

The v5 judge has two outputs — sufficient, or route back. The campaign needed a third, and its final round could only land because it existed: **a finding that is the owner's call — his verbatim copy, pricing, a product-level promise — is filed to the owner, never grounds for a route-back.** Both final judges filed several such questions each while ruling land, stating explicitly that a piece cannot be held hostage to decisions that are not the builder's. Without the lane the last round deadlocks, because every remaining finding was owner-class. The kernel's form, one paragraph in the `judge` skill: the ruling names three lanes — sufficient · route-back with the step and exact scenarios · owner-questions, each question self-contained — and owner-questions land in the work file, where they cannot expire silently.

## The sharpened law — a check must be able to express the failure it rules out

The kernel already holds that a safety net counts only after it has been watched failing on purpose. The campaign's instrument failures — five in one evening, across three parallel sessions — were all one shape *underneath* that law: each was a check whose falsifying case it had no way to represent, so it returned the comfortable answer and looked exactly like a pass. A code search that could not say "reached indirectly". A verification environment that silently re-supplied the very thing whose absence was under test. A completeness gate that counted a loose mention as a listing. The subject plant of Gap 1. A shell status read that measured the wrong command. Watched-fail covers guards; these were *measurements*, and none could have been watched failing because none could fail. The kernel's form, one sentence beside the safety-net law: **a check counts only if it can express the failure it rules out — shown by making it express one; a control that cannot fail proves the instrument, not the claim.**

One borderline case stays out on purpose: the campaign's judges returned structured rulings (typed verdict fields), which worked well but is a harness affordance, not method — the method's bar is already "rules the four citing the records", and the shape they arrive in is the host's business.

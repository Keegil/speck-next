# What died with v11, and where each protection went

Archive — the accounting behind the clean sheet. Nothing here is needed to use or build Speck Next; the kernel's own mechanisms are described in the [README](../../README.md) and [CONTRACT](../../CONTRACT.md).

Speck's proving *doctrine* crossed nearly intact, because the field record shows it caught every real defect: independent review, running the real path, least-privileged users, distrust of tests that assert the bug, safety nets watched failing, judging the outcome not the paperwork, promises that stay delivered, honest uncertainty. **No mechanism crossed by default.** Anything that wants in answers six questions: what recurring failure does it prevent · why can't the project's own code or tests prevent it · kernel or optional extra-care pack · smallest form that keeps the protection · how its value gets measured · what retires it.

The table below names each piece of v11 machinery, the real failure it protected against, and where that protection lives now — because a principle alone replaces nothing: every replacement row says how it works, what it flags, and what it can stop. Nothing is lost history; the v11 line stays intact as the maintained fallback, failure archive, and benchmark opponent.

| Dies with v11 | What it protected against | Where the protection lives now |
|---|---|---|
| 70 skills across project/epic/story command families | work decomposed without discipline | One loop — shape it, build it, prove it, leave the state clear — applied at whatever size the work is. Structure, not a gate; nothing to stop |
| 58 document templates (41% were the same template at three sizes) | incomplete artifacts | Four files: `product.md`, one work file per piece of work, `decisions.md`, `state.md`. The generated state file refuses to show "Proven" or "Live" without its evidence lines |
| The witness-graph engine (3,158 lines, 12 commands, 45 finding codes) | **promises quietly dropped** — flyt shipped 59 of 151 promises undelivered while every gate stayed green | Today: the reviewer's judge-the-whole rule — walk every promise and ask what delivers it now — behavioral, carried by the attack playbook. Planned, on state.md's open list: a kernel check where a promise nothing delivers becomes a named open finding (`promise-dropped`) blocking "Proven" and "Live" for its owner, and an unowned promise blocks the whole product. It earns entry when a real product carries enough promises to drop one silently |
| The 32-validator battery and its prose parsers | green checks that had inspected nothing | Structure only where structure carries weight; plus two tiny survivors, each kept for the failure that earned it: a check that any safety net cited as evidence has been **watched failing on purpose**, and a small mechanical check that flags state lines claiming a verdict without evidence and phrases the product's own copy rules ban |
| The context compiler, receipts, and load-contract files | agents loading the wrong branch of a 70-skill system | Nothing to mis-load at single-digit size. If the kernel ever seems to need a loader again, that is the contract's alarm bell, not a feature request |
| The corpus-budget validator shipped into products | the method outgrowing its own pockets | The same instinct as law in speck-next's own CI (promise 7), with tests proving each limit can trip. Products get nothing |
| The migration marker ladder (4 markers, 4 stages, 10 repair paths) | half-finished upgrades passing as done | The one-shot upgrader owns every era; it leaves **one marker the kernel refuses to run past** until the upgrade is complete — a partial upgrade stays loud, which is the one thing the old ladder got right |
| Play levels (Sprint / Build / Platform) and their conditional slots | heavy work treated lightly | Extra-care packs that switch on where the risk is (money, auth, private data, regulated work). The tier rule matches contract promise 2 exactly: the builder may treat work as bigger than it looks, never smaller; lowering, and any uncertain call, belongs to the owner or the independent reviewer. Task T15 tests the boundary |
| The mandatory per-story chain (clarify, plan, tasks, analysis, retro) | building without thinking | One work file, grown only when the work needs it; learning written down when there is a learning. The thinking-before-running budget (promise 1) keeps the work file from becoming the old big-bang in disguise |
| The engagement ladder, unconditional recheck, and always-written reports | acting on a stale picture of the repo | The generated state file is the single point of re-entry; staleness gets checked in proportion to what's being claimed, and task T17 tests exactly the stale case |
| The meta-methodology apparatus (routing baselines, catalog policies, PR labels) | uncontrolled method change | The one small capability table (promise 8), the 20% maintenance alarm, and this manifest |
| Host adapters for every editor installed everywhere | multi-host support | Generate the one adapter in use; it counts inside the installed-footprint limit |
| The 53-term vocabulary | precision between agents | At most five coined words, and comprehension measured on real readers (promise 6). Internal shorthand may exist in diagnostics; it never reaches the owner |

## Four known v11 bugs, fixed on v11's own line

These are ordinary bugs, not architecture, so they get fixed where they live — on dated issues with regression tests, before the benchmark baseline is measured: the installer shipping Speck's own 18k-line test suite into every product repo · the recheck skill pointing at a report template that doesn't exist · the state skill waiting for a "PASS" another skill is forbidden to say · the lifecycle table reading progress from file presence right under the rule that file presence proves nothing. Fixing them doesn't answer the architecture evidence, and the contest's opponent is snapshotted only after they land, so speck-next beats v11 at full strength or not at all.
